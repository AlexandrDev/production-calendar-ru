# Производственный календарь России

Готовая подписка для Apple Calendar: `calendar.ics`. Пятидневная рабочая неделя; федеральные праздники и сокращённые дни. Региональные и профессиональные праздники не включены.

Источник данных: [КонсультантПлюс — 2027](https://www.consultant.ru/law/ref/calendar/proizvodstvennye/2027/). Проверено 12 ноября 2026 года.

## События

| Даты включительно | Название |
| --- | --- |
| 31.12.2026–10.01.2027 | Новогодние каникулы и Рождество Христово |
| 20.02.2027 | Сокращённый рабочий день |
| 21–23.02.2027 | День защитника Отечества |
| 06–08.03.2027 | Международный женский день |
| 30.04.2027 | Сокращённый рабочий день |
| 01–03.05.2027 | Праздник Весны и Труда |
| 08–10.05.2027 | День Победы |
| 11.06.2027 | Сокращённый рабочий день |
| 12–14.06.2027 | День России |
| 03.11.2027 | Сокращённый рабочий день |
| 04–07.11.2027 | День народного единства |
| 31.12.2027 | Новогодние каникулы и Рождество Христово |

Каждый непрерывный праздничный период — одно событие, включая примыкающие субботы и воскресенья и перенесённые выходные. Обычных выходных вне этих периодов нет. Новогодний период в начале года включает 31 декабря 2026 года, чтобы сохранить его целиком. 31 декабря 2027 года пока отмечено отдельно: продолжение в 2028 году нужно добавить после проверки календаря следующего года.

Все события длятся весь день. В файле нет напоминаний (`VALARM`). События не блокируют занятость (`TRANSP:TRANSPARENT`). Часовой пояс не требуется: даты записаны как `VALUE=DATE`.

## Размещение на GitHub

1. Создайте публичный репозиторий, например `production-calendar`.
2. Загрузите **содержимое этой папки** в корень репозитория, включая `calendar.ics`, `data/`, `generate.py`, `index.html` и `.nojekyll`.
3. Откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку `main`, папку **/(root)**, нажмите **Save**.
4. Дождитесь публикации. Адрес файла будет:

   `https://USERNAME.github.io/production-calendar/calendar.ics`

Замените `USERNAME` и имя репозитория своими значениями. Используйте адрес опубликованного файла, а не страницу `github.com/.../blob/...`.

Документация: [настройка GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Подписка в Apple Calendar

На Mac в приложении «Календарь» выберите **Файл → Новая подписка на календарь**, вставьте HTTPS-адрес `calendar.ics` и оформите подписку. Если подписка должна быть доступна на других устройствах, выберите размещение в iCloud. Установите автообновление, например ежедневно, и отключите предупреждения для подписки.

На iPhone можно использовать **Календарь → Календари → Добавить календарь → Добавить календарь по подписке** и вставить тот же URL. Названия пунктов могут различаться между версиями системы. Если предлагается настройка предупреждений, выключите её.

Подписываться нужно по URL. Открытие скачанного ICS для импорта создаёт локальную копию, которая не получает обновления с GitHub.

В ICS нет уведомлений; дополнительно отключите предупреждения в самой подписке, чтобы исключить настройки напоминаний на устройстве. См. [руководство Apple](https://support.apple.com/ru-ru/guide/calendar/icl32362/27.0/mac/27).

## Добавление следующих лет

1. После публикации проверенного производственного календаря создайте `data/2028.json` по образцу `data/2027.json`. Укажите год, ссылку на источник и события. Данные с сайта автоматически не скачиваются.
2. `start` и `end` — даты **включительно**, формат `YYYY-MM-DD`. `kind` — `holiday` или `short`. Для каждого праздничного периода сохраняйте его `key` из предыдущего года. У сокращённых дней используйте `key: "short"`.
3. Для новогоднего периода используйте `key: "new-year"` и название «Новогодние каникулы и Рождество Христово». Соседние или пересекающиеся периоды с одинаковым ключом объединяются, в том числе через границу года. При добавлении 2028 года удалите временное поле `description` у события 31.12.2027 в `data/2027.json`.
4. В папке репозитория выполните:

   ```sh
   python3 generate.py
   ```

5. Загрузите изменённые JSON и `calendar.ics` в GitHub. GitHub Pages опубликует новую версию; Apple Calendar подхватит её при следующем обновлении подписки.

Python 3.9 или новее; сторонние библиотеки не нужны. Старые JSON сохраняйте: итоговый файл содержит все добавленные годы. Не переименовывайте `calendar.ics` и не меняйте адрес размещения — подписка останется прежней.

UID события определяется ключом и датой начала, поэтому повторная генерация и продление периода с прежним началом не создают новое событие. При изменении начала периода UID изменится; это нормально для полного обновления подписки. Даты не повторяются ежегодно автоматически: переносы и сокращённые дни требуется проверять для каждого года.

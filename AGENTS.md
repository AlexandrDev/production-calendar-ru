# Инструкции для агента

## Источник

Использовать производственный календарь КонсультантПлюс для нужного года: `https://www.consultant.ru/law/ref/calendar/proizvodstvennye/ГОД/`. Проверять год в заголовке и актуальность утверждённых переносов.

- Из раздела «Нерабочие праздничные дни» брать даты и названия федеральных праздников.
- Из раздела «Перенос выходных дней» брать переносы по постановлению и при совпадении праздника с выходным. У новогодних праздников особый порядок: не применять к ним общее правило автоматически.
- Из комментария и отметок календаря брать сокращённые рабочие дни, учитывая рабочие субботы и переносы; не вычислять их только по дате праздника.

## Обработка данных

Календарь рассчитан на пятидневку. Включать праздники, перенесённые выходные и сокращённые дни. Обычные субботы и воскресенья, региональные и профессиональные праздники не добавлять. Не расширять праздники на целые периоды отдыха. Рождество и новогодние каникулы сохранять раздельно.

Хранить данные в `data/ГОД.json`: `year`, `source`, `events`. У события обязательны `start`, `end` (включительно, `YYYY-MM-DD`), `key`, `title`, `kind`; пояснение — в `description`.

- `holiday` — праздник с названием из источника; сохранять существующие ключи праздников.
- `transfer` — отдельное событие «Перенесённый выходной», `key: "transfer"`; в описании указывать исходную дату переноса.
- `short` — «Сокращённый рабочий день», `key: "short"`; в описании указывать сокращение на час и связанный праздник.

Старые годы сохранять. Даты задавать явно для каждого года, без ежегодного повторения. Не создавать дубли. Учитывать, что после переноса исходная суббота может стать рабочей.

## Формирование календаря

После изменения данных или генератора запускать `python3 generate.py` (Python 3.9+, без зависимостей). `calendar.ics` вручную не редактировать. Генератор собирает все годы и объединяет только соседние или пересекающиеся `holiday` с одинаковым ключом; переносы и сокращённые дни остаются отдельными.

Сохранять формат ICS: события на весь день (`VALUE=DATE`), исключительная граница `DTEND`, UTF-8, CRLF, строки до 75 байт с корректным сворачиванием и экранированием. Без напоминаний (`VALARM`), с `TRANSP:TRANSPARENT`. Источник указывать один раз в `URL`, без повторения в описании. UID формировать из ключа и даты начала; без необходимости их не менять. Временные метки обновляются при генерации.

Проверять даты и исходные даты переносов, отсутствие дублей и пересечений выходных с сокращёнными днями, уникальность UID и формат ICS. Годовые итоги сверять с источником, учитывая обычные выходные и рабочие субботы только при подсчёте. Корректные CRLF и пробелы сворачивания не удалять ради `git diff --check`; исходники проверять отдельно.

## Публичная информация и публикация

В `README.md` оставлять только ссылки на подписку и загрузку, дату обновления календаря и охваченные годы. При обновлении календаря актуализировать дату, при добавлении года — диапазон в README и `index.html`. Технические инструкции хранить здесь.

Сохранять имя `calendar.ics` и адрес публикации `https://alexandrdev.github.io/production-calendar-ru/calendar.ics`; для подписки использовать схему `webcal://`.

При публикации коммитить данные, пересобранный ICS и связанные правки, отправлять в `main`. Не включать `.DS_Store` и посторонние изменения. GitHub Pages публикует файл, подписки получают его при следующем обновлении. Не сообщать об успешной отправке до завершения push.
